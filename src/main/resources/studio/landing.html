Wrong types, missing fields, injection markers, no token, forged token, wrong method, oversized body - each changes exactly one thing of a valid request.

Built for safe testing

Because automated testing can hurt a real system, the studio is cautious by default.

✓

Authorisation first

Nothing is sent until you confirm you are authorised. Production-looking URLs need a second, explicit confirmation.

✓

Account lockout guard

Login endpoints get one wrong-password attempt and a verify - never repeated guessing that could lock a shared account.

✓

No junk data

Create / update / delete endpoints get security checks only unless you opt in, so bad requests do not create records.

✓

Secrets stay secret

Passwords, tokens, cookies and OTPs are masked in evidence and never stored in project files.

✓

Honest results

Pass, fail, blocked and not-executed are kept separate. Findings are indicators that need confirmation, not claims.

✓

Private by design

Runs on your machine. No cloud, no API key, no data sent anywhere. The assistant works offline.

Questions

 

Do I need a BRD or documentation?

No. A Postman collection or OpenAPI file plus valid test data is enough. A BRD is optional and adds business rules and flow mapping. Templates are included.

Where do I enter my application URL?

In the "Test my own API" wizard (step 2) and later on the project Overview under Target application, where you can also check the connection.

Do I need an API key or the internet?

No. Everything runs locally. The built-in assistant works without any model; an optional local model can be added later.

Can it test encrypted or session-based APIs?

Yes: cookie sessions, CSRF headers, token chaining and RSA + AES-GCM request envelopes are supported.

Will it change my data?

Only requests you have approved are sent, after you confirm authorisation. Write endpoints get security checks only by default.
